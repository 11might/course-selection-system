7. **重点：SQL 注入（拼接注入）与参数化查询**——见下方专节，学习和实习都要能讲。

## 重点专节：防 SQL 注入（务必记住）

### 什么是 SQL 注入

把用户输入用字符串拼进 SQL，攻击者可篡改语句含义，例如伪造条件、绕过登录、甚至破坏数据。

危险示例（不要这样写）：

```python
sql = "SELECT * FROM user WHERE username='" + username + "'"
cur.execute(sql)
```

若 `username` 被做成类似 `stu1' OR '1'='1`，整句 SQL 的逻辑可能被改掉。

### 正确做法：参数化（占位符）

```python
cur.execute(
    "SELECT ... FROM `user` WHERE username=%s",
    (username,),
)
```

- `%s`：占位，值稍后再填  
- `(username,)`：参数用元组传入（单元素也要逗号）  
- 库会把输入当「数据」处理，而不是当「SQL 语法」

### 为什么实习/工作里常问

- 属于最常见的 Web 安全问题之一  
- 面试常问：什么是注入？你项目里怎么防？  
- 口述一句即可：不拼接用户输入进 SQL，一律用参数绑定 / 占位符。

### 和本项目的关系

登录、按用户名查询都已用 `%s` + 元组，这是正确示范；以后自己写任何 `execute`，默认都走参数化。
