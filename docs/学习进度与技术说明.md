## 七、踩过的坑（备忘）

1. Workbench ⚡ 灰色 → 没连上服务器，或 MySQL 没开。  
2. Restore Workspace / `I:\EE ` Permission denied → 点 Ignore；SQL 以项目文件为准保存。  
3. 两套 MySQL（WAMP vs `I:\EE\mysql-run`）会抢端口、连错库 → **只留 WAMP**。  
4. `uvircorn` / `pymssql` 拼写错误会装错或装失败。  
5. `DROP TABLE` 不能和 `(字段定义)` 写在同一句；建表用 `CREATE TABLE`。  
6. 表名用反引号 `` `user` ``，不要用单引号 `'user'`。  
7. 端口 8080 被 `httpd`（Apache）占用 → 后端改 **8000**。  
8. `Access denied ... password: YES` → `config.py` 密码和 WAMP 不一致（曾试空密码解决）。  
9. 库名别写成 `corse_selection`。

### 2026-08-03 晚（短时，并入上条）

- `execute` 下令查，`fetchone` 取回整行（非只取 username）。
- 登录用 `fetchone`：用户名唯一，一行即可；多行场景才 `fetchall`。
- 失败 `return` 提前结束，不会执行后面发 token；与 `if` 同级缩进靠提前返回，属常见写法。

### 安全必记：防 SQL 注入（学习 + 实习高频）

| | |
|--|--|
| 错误 | `"...'" + username + "'"` 拼进 SQL |
| 正确 | `execute("... %s", (username,))` 参数化 |
| 原因 | 拼接会让输入变成 SQL 语法；占位符把输入当数据 |
| 口述 | 不拼接用户输入；一律占位符/参数绑定防注入 |

本项目登录查询已按正确方式写；以后所有 SQL 默认如此。

### 2026-08-04 补充（注入理解加深）

- 攻击方式：在输入框填入恶意 SQL 片段（含 `; DROP TABLE/DATABASE` 等）。
- 拼接：可能变成多句命令 → 删表/删库/越权。
- `%s`：整段输入只作一个值填空，结构改不了，不会当第二句执行。
